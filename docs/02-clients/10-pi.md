# Pi

[Pi](https://pi.dev/) supports remote MCP over Streamable HTTP. This guide uses
its current built-in MCP support.

## Setup

Add Kite and complete the browser login:

```bash
pi mcp add kite --url https://mcp.kite.trade/mcp --exposure codemode
pi mcp login kite
pi mcp list
```

Start Pi and open `/mcp` to inspect the connection. Run `/reload` if you changed
configuration outside an existing session. Commands write user configuration by
default; `--local` uses project configuration.

An extension registering `/mcp` replaces the built-in session integration.
Check which implementation is active if setup behaves differently.

## Verify the connection

> Use Kite MCP to show my account profile. Do not place any orders.

Inspect the tool result to confirm that the answer comes from Kite.

## Code mode

Pi defaults MCP servers to `codemode` exposure. Discover tools with
`searchTools`, inspect signatures with `describeTool`, and read server
instructions with `describeNamespace("mcp__kite")`.

After confirming the server is named `kite`, this read-only script requests a
quote and reports missing instruments:

```javascript
const result = await tools.mcp__kite__market({
  mode: "quote",
  instruments: ["NSE:INFY"]
});
if (result.isError) {
  text(result);
} else if (result.structuredContent) {
  const { data, meta } = result.structuredContent;
  text({ quotes: data, missing: meta.missing_instruments });
} else {
  text(result);
}
```

Pi scripts receive the MCP `CallToolResult`. Check `isError` even when the
promise resolves. See [[Code Mode]] for pagination, parsing, and approval rules.

## Workflows to try

> Read Kite's compare-quotes recipe, then compare NSE:INFY and NSE:TCS. Include timestamps, missing quotes, and failed requests. Do not place orders.

> Read Kite's holdings-weights recipe. Fetch every holdings page, calculate weights using the reported quantity field, and list any rows excluded for missing prices. Do not rebalance.

> Check the outcome of the browser approval I just reviewed and tell me whether future orders are currently allowed. Do not repeat the order.

The assistant can read these through `help` using:

- `/client-integration/compare-quotes`
- `/client-integration/holdings-weights`
- `/client-integration/approval-status`

These workflows were checked with Pi 1.4.0 against a local mock Kite account.
The checks covered tool discovery, quote timestamps and missing data, failed calls,
holdings pagination and calculations, and browser approval/status. They do not
establish live market-data freshness or exchange execution.

In this Pi version, a failed Kite call can resolve with `isError: true` rather than
throw. Check that field before using the data, and catch rejected calls too. A
completed code-mode script does not mean all its requests succeeded.

## Order approvals and interactive views

When an order needs approval, Pi receives a browser link. Open it in any browser,
sign in to the matching Kite account, then approve or decline the request.
Return to Pi and ask it to check the outcome. Do not repeat the original request.

You can optionally allow future orders from Pi on that page. Leave the checkbox
unchecked to review each action. See [[Order Approvals]] for the permission's
expiry and how to require approval again.

Pi does not render MCP Apps; use ordinary data tools for analysis.
